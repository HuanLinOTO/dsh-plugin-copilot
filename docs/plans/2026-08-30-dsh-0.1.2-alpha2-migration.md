> 所有 alpha2 结论均以只读 git 命令（`git -C D:/Projects/deepseek-harness/dsh show/diff/grep <tag>:…`）对 `dsh-v0.1.2-alpha.2` 源码核实。

## 结论 —— ⚠️ 需适配（轻量，约 4 行源码 + 重建 lib/）

host 半侧有 **2 处类型级 import 断裂**（上游把 `settingsNamespace()` 从 `@deepseek-ai/dsh-settings` 移除、把 `JsonValue` 从 `@deepseek-ai/dsh-tools` 包根撤下），必须改 `src/index.ts` 与 `src/tools.ts` 后重建 `lib/`；client 半侧与全部运行时服务面（authorization/credentials/settings/tools/llm/webServer/invariants、slots 契约、locale、client-store、模块加载器契约）在 alpha2 中零破坏，业务逻辑无需任何改动。

## 迁移步骤

> 前置（人类执行，本指南不代跑）：先按 `AGENTS.md` 的「更新 DSH 源码 checkout」SOP 把 `~/.dsh/source/current`（与 dev clone）拉到 ≥ `dsh-v0.1.2-alpha.2`，并在 `$src` 完成 `pnpm install --prefer-offline` + `pnpm run build`。不完成这步，下面的类型修改无法验证（`paths` 解析不到新 `lib/types`）。

1. **改 `src/index.ts`（2 行）** —— 适配 `settingsNamespace` 移除：
   ```ts
   // 第 24 行：删掉具名导入 settingsNamespace，仅留类型
   - import { settingsNamespace, type SettingsNamespace } from '@deepseek-ai/dsh-settings'
   + import type { SettingsNamespace } from '@deepseek-ai/dsh-settings'

   // 第 46 行：改为类型断言（brand 由调用方保证；alpha2 的 register 内部仍会按
   // ^[a-z][a-z0-9-]*$ 做运行时校验，'dsh-plugin-copilot' 匹配）
   - export const CARD_NAMESPACE = settingsNamespace('dsh-plugin-copilot')
   + export const CARD_NAMESPACE = 'dsh-plugin-copilot' as SettingsNamespace
   ```
   说明：alpha2 的 `register/get/update` 接受泛型字符串且首分支 `Value extends SettingsNamespace` 仍放行 branded 值，故 `src/index.ts:64` 的 `PI_AI_NS = COPILOT_SETTINGS_NS as SettingsNamespace`、`settings.get(PI_AI_NS)`、`settings.update(PI_AI_NS, …)` **均无需改动**。
2. **改 `src/tools.ts`（约 3 行）** —— 适配 `JsonValue` 撤下：
   ```ts
   // 第 10 行删除：
   - import type { JsonValue } from '@deepseek-ai/dsh-tools'
   // 文件内（import 区之后）补一个与 @deepseek-ai/dsh-util-values 逐字一致的本地类型：
   + type JsonValue = null | boolean | number | string | JsonValue[] | { [key: string]: JsonValue }
   ```
   备选 B（不推荐，仅为完整性）：把 `@deepseek-ai/dsh-util-values` 加进 `peerDependencies`（optional）+ `pnpm-workspace.yaml` overrides + `tsconfig.json` paths（指向 `packages/util/values/lib/types/index.d.ts`），从新包 import `JsonValue`。一个纯类型不值得新增 peer，方案 A 结构化等价且零新依赖。
3. **（可选，建议）`package.json`**：`peerDependencies` 中 9 个 `@deepseek-ai/dsh-*` 从 `^0.1.2-alpha.1` 对齐为 `^0.1.2-alpha.2`（非必须，旧范围已满足）；版本号按 semver 升一档（如 `0.2.1`）。`files`、`dsh.bundle.patch`、`dsh.client.inject`、`cordis.patch.yml` **均无需改动**。
4. **验证三件套 + 重建 `lib/`**（由维护者在插件目录执行）：
   ```powershell
   pnpm run typecheck   # 上述 2 处改动后应零错误
   pnpm test            # 48 用例（tests 仅 import authorization/credentials/cordis —— 均零变更包）
   pnpm run build       # tsdown（lib/index.js + lib/invariant.js + lib/client.js）+ tsc 声明
   ```
   注意 build 脚本不含 `rm -rf lib`（tsdown `clean: true` 已覆盖 host 入口；如需干净重建先手动 `Remove-Item lib -Recurse -Force`，Windows 坑）。**本插件无 link:/overrides 之外的重建前置**：typecheck/test 经 `~/.dsh/source/current` 解析，升级 alpha2 后无需改 `tsconfig.json`/`pnpm-workspace.yaml`。
5. **profile 端生效**：
   - `link:` 引用（`dsh plugin --profile web add link:D:/Projects/deepseek-harness/dsh-plugin-copilot`）：**无需重装**，第 4 步重建 `lib/` 后 profile `node_modules/@huanlin/dsh-plugin-copilot/lib/` 直接可见新产物；
   - 对外发布（github:/npm）：走 huanlinoto 发布 SOP —— 重建 `lib/` → `git add lib/ && git commit && git push` → `dsh plugin --profile web update @huanlin/dsh-plugin-copilot`；或 `npm pack --dry-run` 核对 `files`（`lib/` + `cordis.patch.yml`）后 `pnpm publish`（`publishConfig.access: public` 已声明）。
6. **重启与刷新（人类执行）**：重启 `dsh web` 进程 + 浏览器 `Ctrl+Shift+R` 硬刷新。
